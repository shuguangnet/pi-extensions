# workspace-switcher

在 pi 里跨目录工作，并且让对话在你切走之后继续跑。

两个命令：

| 命令 | 用途 |
|---|---|
| `/ws` | 工作区切换器：目录 → 会话 → 恢复 / 新开 / 丢到后台跑 |
| `/ws <目录>` | 直接进入指定目录（`/ws ~/work/demo`） |
| `/wsj` | 后台任务面板：查看输出、追加指令、中止、结束、切入会话 |

## 能力

### 1. 切换目录（不用退出 pi 重进）

`/ws` 会把所有用过 pi 的目录列出来（按最近活动排序，带会话数）：

```
📁 ~/saas-ui            ·  15 个会话  ·  6 分钟前
📁 ~/project/gyp        ·  26 个会话  ·  16 小时前
➕ 输入目录路径…
🛰 后台任务（2 个在跑）
✖ 关闭
```

选目录后进入会话列表，可以做三件事：

- **恢复任意会话**：跨文件夹挑一个历史会话切过去，pi 的 cwd 跟着那个会话走；
- **在该目录新开会话**：为还没用过 pi 的目录也能直接开工；
- **在该目录新开后台任务**：见下。

### 2. 让对话在后台继续跑

后台任务 = 一个独立的 `pi --mode rpc` 子进程，跑在你指定的目录、可绑定指定会话。
它和主 pi 完全隔离：

- 主 TUI 换目录、换会话、甚至 `/reload` 都不会打断它；
- 跑完/失败时在状态栏（🛰）和通知里告诉你；
- 想接管时在 `/wsj` 里选「👁 切入这个会话」：先结束子进程，再把主 TUI 切到那个会话继续聊；
- 空闲的任务可以继续追加指令（`💬 继续对话`），也可以随时中止当前这轮 / 结束任务。

## 安装

```bash
mkdir -p ~/.pi/agent/extensions
ln -s "$HOME/pi-extensions/plugins/workspace-switcher" ~/.pi/agent/extensions/workspace-switcher
```

改完 `/reload` 生效，或重启 pi。

## 自定义（`config.ts`）

| 配置 | 默认 | 说明 |
|---|---|---|
| `PI_BINARY` | `pi` | 后台任务用的可执行文件（环境变量 `PI_WS_PI_BINARY`） |
| `MAX_JOBS` | `4` | 后台任务并发上限（`PI_WS_MAX_JOBS`） |
| `INHERIT_MODEL` | `true` | 后台任务沿用当前会话的模型 |
| `AUTO_APPROVE_DIALOGS` | `false` | 后台任务遇到确认弹窗是否自动同意（`PI_WS_AUTO_APPROVE=1`） |
| `EXTRA_PI_ARGS` | `[]` | 追加给后台 pi 的参数，例如 `["--thinking", "high"]` |
| `MAX_DIRS` / `MAX_SESSIONS_PER_DIR` | 25 / 25 | 面板里最多列出多少目录 / 每个目录多少会话 |
| `LIST_CACHE_MS` | 20000 | 目录会话索引的缓存时长 |

## 原理与边界

**cwd 是怎么切的。** 扩展 API 不能直接改工作目录，但 runtime 会跟随会话 header 里的 `cwd`。
所以「在目录 X 新开会话」= 先在 X 下落一个合法的空会话文件（只写 header），再 `switchSession` 过去，
cwd 就跟着落到 X。「恢复历史会话」则是直接 `switchSession` 到那个会话文件，cwd 自然跟着它。

**后台任务为什么会继续跑。** 它不在主进程里，而是你自己这套 pi 的第二个进程（`pi --mode rpc`），
通过 JSONL 协议投喂指令、读取事件。主进程退出（`/quit`、Ctrl+D）时插件会一起把子进程收掉，
避免留下孤儿进程。

**已知限制：**

- 当前会话正在跑回复/工具时，切走会中断它（pi 内核行为），切换前会弹确认。
- 同一个会话文件不能被两个进程同时写。把「当前打开的会话」丢到后台会被拦截；
  `/wsj` 里切入后台会话时也会先结束子进程。
- 后台任务默认不自动同意项目信任之类的弹窗（一律取消），避免在你没看过的新目录里自动放权；
  确实需要就打开 `AUTO_APPROVE_DIALOGS`。
- 目录/会话索引来自 pi 的 session 扫描，第一次打开面板可能要一两秒；之后 20 秒内走缓存。
